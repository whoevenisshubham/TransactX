# ADR-036: Bounded optional investigator generation

Status: **IMPLEMENTED IN M3 PACKAGE; RUNTIME INTEGRATION PENDING B11**

## Context

The investigator must remain useful with no provider key or paid budget. Optional generation receives redacted evidence and reviewed runbooks, both of which can contain hostile instructions. A Work subscription is not an API budget. Provider failures, parallel requests, stale snapshots, and syntactically valid but semantically false citations must not affect financial state or produce an authoritative report.

## Decision

- `evidence_only` is the default and calls no provider. `llm` is selected only by trusted server configuration and requires a provider plus transactional input/output-token and integer micro-USD reservations. The default limits are zero; a paid provider is rejected without a positive reviewed currency allowance, while an explicit loopback provider may use zero cost.
- The OpenAI adapter uses the Responses API with `text.format` strict JSON Schema output. Function tools use strict schemas with every property required and `additionalProperties:false`; parallel tool calls are disabled. This matches the official OpenAI documentation checked on 12 October 2026.
- The only non-OpenAI endpoint accepted by the adapter is explicit loopback HTTP for a locally configured compatible fixture/model. The OpenAI API key is sent only to the exact HTTPS `api.openai.com/v1/responses` endpoint. Arbitrary provider/model URLs are rejected.
- Actor, role, and selected-payment scope never enter provider tool schemas. The orchestrator injects the selected payment after strict model-argument decoding and executes only the C2 read registry. There is no SQL, shell, URL, mutation, recovery-control, chaos-control, settlement, reversal, or reroute tool.
- Provider calls are bounded to two rounds, eight unique tools, a conservative 8,000-input-token cap, and 1,200 output tokens. The response body, tool arguments, tool outputs, runbook chunks, trace spans, windows, and request deadline are independently bounded.
- Evidence/retrieval hashes and usage reservation identity are saved before generation. Provider output, actual nullable usage, request IDs, model identity, tool outputs, and continuation items are checkpointed before another round. A changed evidence snapshot is rejected.
- Strict schema conformance is necessary but not sufficient. The server checks assertion field/value/entity/evidence meaning against typed evidence, rejects unknown citations and stale snapshot identity, and deterministically re-renders financial fact text, summary, missing evidence, coverage, and recommendations. Provider prose may remain only as an explicitly labelled inference with known evidence citations.
- Refusal, timeout, 429, malformed output, unsupported facts, budget exhaustion, tool rejection, or usage-commit failure produces a sanitized failed job with the deterministic evidence-only report retained when possible. No provider failure mutates or invokes the payment kernel.

## Consequences and rollback

M2 must implement epoch-fenced checkpoints and transactional concurrent reservations in migration 000027 before enabling `llm`. Set provider mode to `evidence_only` to roll back generation without changing evidence reads or saved historical reports. Live provider/RAG capability is not verified unless a separately authorized nonzero budget produces a committed evaluation artifact; fixture HTTP tests are not a live-provider result.

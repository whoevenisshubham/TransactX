# C0-C4 integration specification (tx.v2.1)

The typed evidence interfaces, immutable synthetic fixtures, C1 reviewed corpus, C2 evidence-only orchestration, C3 optional provider/grounding path, C4 fixed evaluation and M3-owned `PostgresInvestigationStore` adapter compile independently. Do not mount a fixture reader, `MemoryCorpus`, or `MemoryInvestigationStore` in production. Shared contract remains unchanged.

The 13 October audit of `origin/v2/m2-reliability-platform` at `c64a9e62870e4ed802910b9ee84e0dee73ffc9bb` found that B11 independently defines another investigator model/service/repository and a smaller migration contract. It is not a drop-in implementation of these interfaces. Retain the M3 service and adapt M2's operations reader, analytics repository and PostgreSQL composition; do not compile or mount both investigator services. The exact field/table differences, adapter sequence and live gates are recorded in `M2_COMPATIBILITY_AUDIT.md`.

M2 implements EvidenceReader with existing JWT middleware and trusted actor, role and selected payment scope. Use a 3-second read deadline, central read-only repeatable-read snapshot then bounded participant reads, exact original target/operation identities, safe errors and canonical redacted snapshot hashing. Unknown/timeout is not FAILED. Do not trigger recovery/reconciliation/integrity/health sampling from reads. Wrong identity fixture is a negative authorization input, not a valid reader result. Injected document is untrusted test data, outside the approved corpus.

For the audited M2 operations DTO, place an `EvidenceJSONSource` implementation in the runtime composition layer, where it can import both packages without a cycle. Parse the selected payment as UUID, call the operations reader, and serialize its returned `tx.evidence.v1` DTO. Mount that source through `BridgedEvidenceReader`: it rejects invalid trusted scope or selected-payment mismatch before the M2 read, then calls `DecodeTrustedEvidenceBundle`. The decoder enforces a 1 MiB input limit, rejects unknown/trailing JSON, validates shared array/source bounds and binds the result to the authenticated selected payment. Its tests are a package gate, not proof of a live database read.

M2 migration 000027/forward-migration specification: investigation_jobs (UUID job and selected-payment identities, authenticated actor identity, actor-scoped idempotency key + request hash uniqueness, status/mode, lease owner/epoch/expiry, deadline, creation/completion timestamps, `provider_call_pending`, and a complete validated `job_payload`); investigation_checkpoints or the equivalent durable job payload (exact immutable evidence/document hashes, bounded tool outputs, attempts, provider-call-pending marker, pending tool calls, provider continuation/report, provider request/result identity); investigation_reports or equivalent terminal payload (validated report JSON, snapshot/prompt/corpus/model versions, actual nullable usage); usage_reservations (job/provider/request identity, separate reserved input/output and integer micro-USD allowance, actual nullable usage, reserved/uncertain/completed state); investigation_usage_limits (aggregate input/output and micro-USD limits). Retained legacy reservation columns must be nullable or removed so the M3 insert can execute, and one reservation per job must be unique. An upgrade must backfill a complete M3 payload or explicitly archive incompatible legacy rows; `job_payload = '{}'` is not a valid migration. Migration success/checksum verification alone is not store acceptance.

The C1 PostgreSQL repository additionally requires `corpus_versions(version text primary key, manifest_sha256 text, status staging|active|retired, chunk_count integer, created_at, activated_at, deactivated_at)` with a partial unique index allowing one active version. `runbook_chunks` requires `(corpus_version, chunk_id)` primary key plus `document_path`, `heading`, positive `start_line`/`end_line`, `source_sha256`, `content_sha256`, `implementation_status existing|planned`, `tags text[]`, `allowed_roles text[]`, immutable `content`, and a stored `tsvector` built with the `simple` configuration over heading/content. Add GIN indexes for the vector and tags. Retiring a corpus never deletes its chunks because saved report citations resolve by version and chunk ID. Exact DDL, retention and migration tests remain M2-owned; `postgres_corpus_integration_test.go` contains disposable test-only DDL and is not a canonical migration.

M2 configuration/mounting: run `go -C backend run ./internal/investigator/cmd/corpus -root .. -manifest ../docs/runbooks/corpus-manifest.json -database-url <url>` to stage the exact committed manifest, validate count/hash, then repeat with `-activate` only after review. Retrieval uses `websearch_to_tsquery('simple', $1)`, role containment, parameterized tag boost, stable chunk-ID tie breaking and topK <=5. Keep the committed manifest inactive until the durable migration and staged validation exist.

Investigator configuration remains evidence-only by default, with paid budget zero and an explicit provider allowlist/configuration; 30-second job deadline; one active job per actor/two global, 3 creates/minute/actor; LLM one active call, 2 rounds, 8 tools, topK=5, 8000 input/1200 output tokens. `CostLimitMicrousd` is an integer per-job worst-case allowance derived from a reviewed provider/model price; M2 applies the aggregate cost limit to its configured UTC daily budget window. The exact OpenAI endpoint requires a positive allowance, while an explicit loopback provider may reserve zero cost. Never decode TrustedScope from model input. Transactional usage reservations and epoch-fenced checkpoint writes are required before generation.

C2 store/mount contract: `Create` enforces actor-scoped idempotency over the request hash; `Claim` advances a lease epoch; every `SaveCheckpoint` rejects a stale owner/epoch. Persist `EvidenceAttempts` and `RetrievalAttempts` before each external read, then persist the exact output hash/timeline before report construction. Worker cancellation leaves a resumable running job; the absolute deadline and two-attempt core bounds prevent unlimited retries. `api.go` exposes the exact create/result DTOs without auth fields. M2 must call `DecodeCreateInvestigationRequest`, which enforces a 32 KiB bound, unknown-field rejection and exactly one JSON value, then inject `TrustedScope` from JWT authorization, call `Service.Start`, and wrap `CreateResponse`/`PublicInvestigation` in the common `{requestId,data}` envelope. Do not decode or silently ignore actor, role, provider, mode, SQL, URLs or mutation requests from the body.

`internal/investigator/storetest.Run` is the executable durable-store contract. A PostgreSQL integration test supplies a clean schema-isolated factory with configurable aggregate input/output-token and integer micro-USD budgets. The suite checks actor-scoped idempotency and conflicts, one active job per actor/two global, one active provider dispatch globally, scope-denied reads, caller-copy isolation, claim exclusivity, lease-epoch fencing, checkpoint resume, identity-tamper rejection, terminal report persistence, concurrent token/cost reservation overspend, lease-fenced/idempotent finalization and an idempotent uncertain transition that retains its full allowance. The harness passes against both `MemoryInvestigationStore` and the M3-owned `PostgresInvestigationStore` in normal and race runs. `store_contract_test.go` uses UUID-shaped test-only DDL; production code contains no schema bootstrap. B11/C6 requires M2's canonical migration and runtime composition to supply that adapter, then pass the same suite against the actual migrated schema rather than repeating the test-only factory. The adapter rejects incomplete/corrupt stored payloads before replay, GET or claim and normalizes PostgreSQL lease timestamps to microsecond precision.

`TestPostgresInvestigationStoreCanonicalSchemaConformance` is the explicit canonical-migration gate. It creates no schema or DDL, preflights every required column/nullability plus the unique reservation-per-job constraint, and then runs the same five store cases against an already migrated `public` schema. Because it truncates `investigation_jobs`, `investigation_usage_reservations` and `investigation_usage_limits` between cases, it refuses to run unless both `M3_CANONICAL_STORE_DATABASE_URL` and `M3_CANONICAL_STORE_RESET_DATABASE` are set, the latter exactly matches `current_database()`, and the database name ends in `_test`. Use a dedicated disposable database only. Example: set the URL to a migrated `transactx_m3_test` database, set `M3_CANONICAL_STORE_RESET_DATABASE=transactx_m3_test`, then run `go test -count=1 -run '^TestPostgresInvestigationStoreCanonicalSchemaConformance$' ./internal/investigator` and repeat with `-race`. A skip without those variables is not canonical-schema evidence.

The C2 registry allowlists only evidence, recovery-attempt, related-reconciliation, trace, operational-window and runbook reads. It validates selected payment, known trace/run identities, route entity/window limits, unknown fields and output bounds. M2 supplies real readers; source reads remain non-mutating and keep their existing deadlines. The service always executes the two deterministic core tools (evidence and retrieval) and produces a grounded evidence-only report; optional model-directed rounds remain disabled unless the C3 provider path is explicitly configured with a nonzero authorized budget.

C3 configuration: keep `ModeEvidenceOnly` unless an owner explicitly supplies a provider configuration and nonzero transactional token/cost budget. `ModeLLM` requires the committed `tx.investigator.prompt.v1`, at most 8,000 conservatively estimated input tokens, 1,200 output tokens, two provider rounds, one active provider call globally and eight unique read tools. The OpenAI adapter accepts only exact `https://api.openai.com/v1/responses` (with server-side key) or explicit loopback HTTP for a configured compatible local endpoint; arbitrary URLs are rejected and an OpenAI key is never forwarded to loopback. No environment names or shared config parsing are added here because M2 owns composition.

Reserve the full worst-case input-token, output-token and integer micro-USD allowance transactionally before the first provider call. A token cap alone is not permission to spend: paid providers fail configuration without a positive reviewed currency allowance. `ReserveUsage`, `CompleteUsage` and `MarkUsageUncertain` receive the claimed job and reject a stale lease. The false-to-true in-flight checkpoint transition atomically admits at most one provider dispatch globally. Checkpoint the reservation ID, prompt version, in-flight marker, provider request/model IDs, output hash, nullable actual usage, continuation items, pending report/tool calls and each tool output. A lease takeover seeing an in-flight marker marks usage uncertain without another provider request; a checkpointed response/tool call resumes locally. Refusal, timeout, 429 and other failures after provider invocation also retain the entire uncertain reservation. Do not silently release or retry them. `CompleteUsage` atomically persists the validated terminal job/report and actual usage and is idempotent for that completion; unreported usage consumes its conservative allowance rather than becoming zero. M3's memory reservation store proves these reference semantics but is not database acceptance.

The provider-facing tool schemas omit actor, role and payment ID; the orchestrator injects selected payment after strict decoding. Final validation checks assertion meaning, not just citation existence, then replaces provider-controlled financial fact prose, summary, coverage, missing evidence and recommendations with deterministic renderings. On refusal, timeout, 429, malformed output, changed snapshot, unknown evidence, wrong typed value, tool rejection or usage failure, return a sanitized failed job while retaining the evidence-only report when possible. ADR-036 is package-local pending M1/M2 placement during integration.

M1 should consume `evaluation/results.json` `uiFixtures` after shared schema validation. Preserve mode labels, partial/missing evidence, safe provider-failure fallback, nullable usage and snapshot drilldowns. `validatedLLMFixtureOnly` exists to exercise rendering and is not a live-provider result. The C0 reports remain expected values, not runtime output.

# C0-C1 integration specification (tx.v2.1)

The typed evidence interfaces, immutable synthetic fixtures, and C1 reviewed corpus compile independently. Runtime investigator orchestration remains pending in C2-C4. Do not mount a fixture reader or `MemoryCorpus` in production. Shared contract remains unchanged.

M2 implements EvidenceReader with existing JWT middleware and trusted actor, role and selected payment scope. Use a 3-second read deadline, central read-only repeatable-read snapshot then bounded participant reads, exact original target/operation identities, safe errors and canonical redacted snapshot hashing. Unknown/timeout is not FAILED. Do not trigger recovery/reconciliation/integrity/health sampling from reads. Wrong identity fixture is a negative authorization input, not a valid reader result. Injected document is untrusted test data, outside the approved corpus.

M2 migration 000027 specification: investigation_jobs (UUID, actor UUID, selected payment UUID, actor-scoped idempotency key + request hash uniqueness, status/mode, lease owner/epoch/expiry, deadline, creation/completion timestamps); investigation_checkpoints (job + sequence, exact immutable evidence/document hashes, bounded tool outputs, provider request/result identity); investigation_reports (job, validated report JSON, snapshot/prompt/corpus/model versions, actual nullable usage); usage_reservations (actor/job/provider/request identity, reserved token/cost cap, actual usage, uncertain/completed state).

The C1 PostgreSQL repository additionally requires `corpus_versions(version text primary key, manifest_sha256 text, status staging|active|retired, chunk_count integer, created_at, activated_at, deactivated_at)` with a partial unique index allowing one active version. `runbook_chunks` requires `(corpus_version, chunk_id)` primary key plus `document_path`, `heading`, positive `start_line`/`end_line`, `source_sha256`, `content_sha256`, `implementation_status existing|planned`, `tags text[]`, `allowed_roles text[]`, immutable `content`, and a stored `tsvector` built with the `simple` configuration over heading/content. Add GIN indexes for the vector and tags. Retiring a corpus never deletes its chunks because saved report citations resolve by version and chunk ID. Exact DDL, retention and migration tests remain M2-owned; `postgres_corpus_integration_test.go` contains disposable test-only DDL and is not a canonical migration.

M2 configuration/mounting: run `go -C backend run ./internal/investigator/cmd/corpus -root .. -manifest ../docs/runbooks/corpus-manifest.json -database-url <url>` to stage the exact committed manifest, validate count/hash, then repeat with `-activate` only after review. Retrieval uses `websearch_to_tsquery('simple', $1)`, role containment, parameterized tag boost, stable chunk-ID tie breaking and topK <=5. Keep the committed manifest inactive until the durable migration and staged validation exist.

Investigator configuration remains evidence-only by default, with paid budget zero and an explicit provider allowlist/configuration; 30-second job deadline; one active job per actor/two global, 3 creates/minute/actor; LLM one active call, 2 rounds, 8 tools, topK=5, 8000 input/1200 output tokens. Never decode TrustedScope from model input. Transactional usage reservations and epoch-fenced checkpoint writes are required before generation. Mount common-envelope authenticated POST/GET routes only after C4/B11. Provider interface currently describes report generation only; bounded typed tool-call extensions belong to C2/C3, without arbitrary SQL/URL/shell/mutations.

M1 may consume JSON fixtures' evidence/report payloads after shared schema validation. Preserve mode/partial/unknown/trace missing states and snapshot drilldowns. These C0 reports are expected fixture values, not runtime output or live LLM results. No runtime financial grounding claim is made by C0's fixture tests.

C1 local result: six manifest-only documents produce 35 deterministic chunks. Eight reviewed cases reach recall@5 1.000 in the offline deterministic evaluator. The disposable PostgreSQL lifecycle test covers staging, duplicate ingestion, role filtering, parameterized injection-shaped queries, removal on version switch and old citation resolution when `DATABASE_URL` is present. An unset database URL is a recorded skip, not a PostgreSQL pass. No live corpus is active yet.
